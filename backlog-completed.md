## 2. Security

- [x] **P0 — No authentication on any route; `lanToken` is unwired.** `AppConfig.lanToken` exists but is never read. In Docker the server binds `0.0.0.0`, exposing the full API and all of `/media` to the LAN with zero auth. Implement LAN-token auth (or document the risk and bind localhost by default). (`shared/src/config.ts:23`, `server/src/index.ts:123`) — *Fixed: new `server/src/auth/lan-token.ts` middleware gates `/api` and `/media` when `lanToken` is set (no-op by default); wired into Settings (generate/show/clear, same pattern as the webhook secret) and the web client (`Authorization` header for fetches, `?token=` for `<audio>`/`<a>` media URLs, captured automatically from a shared `?token=` link). Covered by `lan-token.test.ts`.*
- [x] **P1 — Detail response leaks the absolute recordings path.** `recordingsDir` (host filesystem path) and `mediaBase` are returned to the browser and aren't even in the typed response. (`server/src/routes/recordings.ts:171`, `shared/src/api.ts:54-56`) — *Fixed: dropped `recordingsDir` from the `/api/recordings/:id` response (confirmed unused by the web client).*
- [x] **P1 — Webhook signatures are replayable.** The HMAC covers only the body — no timestamp header in the signed content, so a captured request can be replayed indefinitely. Add `X-Applaud-Timestamp` to the signature input. (`server/src/webhook/sign.ts`) — *Fixed: `signPayload` now signs `${timestamp}.${body}` and every send includes `X-Applaud-Timestamp`; README verification snippets and tests updated to match.*
- [x] **P1 — Docker container runs as root with no healthcheck.** Add `USER node` to the runtime stage and a `HEALTHCHECK` against port 44471. (`Dockerfile`) — *Fixed: runtime stage now chowns `/app` and the volume mount points to the built-in `node` user and runs as it; added a `HEALTHCHECK` against a new unauthenticated `/api/health` endpoint (kept exempt from `lanToken` gating so it still works when LAN auth is enabled).*
- [x] **P1 — Path-traversal guard has no test.** The `/media` containment check (`realpathSync` + `path.relative`) is correct but security-critical and untested. (`server/src/routes/media.ts:22-40`) — *Fixed: exported `resolveSafe` and added `media.test.ts` covering traversal, URL-encoded traversal, NUL-byte injection, and containment.*

### 2026-07-27 security pass (from the 2026-07-21 review)

- [x] **P1 — Stored XSS via same-origin `/media`.** `.svg` → `image/svg+xml` and `.md`/`.txt` were served inline from the SPA's own origin, with **no** `X-Content-Type-Options: nosniff`, `Content-Disposition`, or CSP anywhere. A recording folder containing an `.svg` attachment (auto-discovered and surfaced as `/media/...` URLs and in webhook payloads) executed arbitrary JS in the token-bearing app origin when opened. (`server/src/routes/media.ts:19,67`, `server/src/index.ts`) — *Fixed: new `security/headers.ts` sets `nosniff` + `Referrer-Policy: no-referrer` + `X-Frame-Options: DENY` + an app CSP on every response (the CSP hashes the inline theme-bootstrap script from the built `index.html`, so script-src needs no `'unsafe-inline'`). `/media` overrides it with `default-src 'none'; sandbox`, and a new `contentDisposition()` policy serves only audio/raster images inline — `.svg`/`.svgz`/`.html`/`.xml`/`.pdf` become `application/octet-stream` + `Content-Disposition: attachment`, as does anything unknown. `AttachmentsCard` no longer thumbnails `.svg` (it lists it as a download). 13 new tests; verified live that `evil.svg` returns octet-stream + attachment + sandbox CSP and that the CSP hash matches the built bundle.*
- [x] **P1 — Webhook test/log is an SSRF read-oracle.** `test-webhook` validated only `z.string().url()`, fetched it, and returned up to 500 chars of the response body to the caller; the same snippet was persisted to `webhook_log` and readable via `GET /api/webhooks/log`. Redirects were followed by default, defeating any host allowlist. (`server/src/routes/config.ts:89`, `server/src/webhook/post.ts:198,306-335`) — *Fixed: new `security/ssrf.ts` + `security/ip.ts`. Both `testWebhook` and `fireRaw` assert the target first: http(s) only, no embedded credentials, and every DNS answer must be a public address (IPv4 private/CGNAT/link-local/multicast/reserved, IPv6 ULA/link-local/multicast, plus IPv4-mapped, NAT64- and 6to4-embedded v4). Both fetches use `redirect: "manual"`; a 3xx is logged as a failed attempt instead of being chased. A rejected target short-circuits the retry schedule. `APPLAUD_WEBHOOK_ALLOW_PRIVATE=1` re-enables LAN/localhost targets (n8n, Home Assistant) and is named in the error message so it's discoverable; the config POST and `test-webhook` schemas also reject non-http(s) URLs up front. **Behavior change:** an existing localhost/LAN webhook URL needs that env var.*
- [x] **P1 — Docker exposes the full API + all recordings unauthenticated by default.** In container mode (`APPLAUD_CONFIG_DIR` set) the server binds `0.0.0.0`, skips the PID lock, and `lanToken` defaulted to `null`, so `requireLanToken` was a no-op — anyone who could route to the container read every recording/transcript and could POST config. (`server/src/index.ts:84,137`, `server/src/auth/lan-token.ts:16`) — *Fixed: `ensureContainerAuth()` runs before the listener in container mode — it adopts `APPLAUD_LAN_TOKEN` (refusing to start if shorter than the minimum) or generates a 48-hex-char token, persists it, and prints a banner with the `?token=` URL to the container log. `APPLAUD_ALLOW_NO_AUTH=1` opts out for setups with an authenticating proxy in front. Documented in the README's new "Docker access token" section and in `docker-compose.yml`.*
- [x] **P2 — No Host/Origin validation → DNS-rebinding / CSRF.** No CORS, Host allowlist, or CSRF protection; on the default `lanToken = null` localhost install, a malicious page the user visits could rebind its domain to `127.0.0.1:44471` and then read/drive the API same-origin. (`server/src/index.ts`) — *Fixed: `security/host-check.ts` allowlists IP literals, `localhost`, `.local`/`.lan`/`.internal`/`.home.arpa`/`.ts.net` suffixes, the configured `bind.host`, and `APPLAUD_ALLOWED_HOSTS` (supports `*.domain` and `*`); anything else gets 403 with a message naming the env var. Applied globally, so the SPA is covered too. Verified live: `Host: rebind.evil.example` → 403, `127.0.0.1` → 200.*
- [x] **P2 — Timing-unsafe LAN-token comparison.** Plain `===` on the bearer/query token while the codebase already used `crypto.timingSafeEqual` for webhook signatures. (`server/src/auth/lan-token.ts:23`) — *Fixed: `secretEquals()` SHA-256s both sides and compares with `timingSafeEqual`, so unequal lengths neither throw nor leak length.*
- [x] **P2 — `lanToken` has no minimum length/entropy requirement.** `z.string().optional()` accepted a 1-character token. (`server/src/routes/config.ts:41`) — *Fixed: the patch schema enforces `LAN_TOKEN_MIN_LENGTH` (16, env-tunable) while still accepting `""` (clear) and the redaction sentinel (preserve); the container-mode bootstrap generates 48 chars and rejects a too-short `APPLAUD_LAN_TOKEN`.*
- [x] **P2 — `validate-recordings-dir` is an arbitrary mkdir + filesystem oracle.** Took any string, `path.resolve`d it, `mkdirSync(recursive)` it, and reported existence/writability/free bytes — a "create a directory anywhere the process can write" primitive and a filesystem probe if the auth gate were bypassed. (`server/src/routes/config.ts:103-142`) — *Fixed: creation is opt-in (`create: true`) and non-recursive — a single leaf under an existing parent, so it can't scaffold a tree. Raw errno strings are replaced with error codes, non-directory paths are rejected, and the route is rate-limited. The setup wizard now checks read-only and offers an explicit "Create it" button.*
- [x] **P2 — No rate limiting on auth/config/media.** Nothing throttled these routes, enabling brute-forcing a weak `lanToken` and using `test-webhook` as an unthrottled SSRF scanner. (`server/src/index.ts`, `server/src/routes/`) — *Fixed: `security/rate-limit.ts` (dependency-free fixed-window limiter per client IP, with bucket sweep and `Retry-After`): 600/min on `/api`, 900/min on `/media`, 20/min on `test-webhook` and `validate-recordings-dir`, and 20 failed token attempts/min before a client gets 429s (failures only — a valid token is never limited). All caps env-tunable. Verified live.*
- [x] **P3 — LAN token leaks via the `?token=` query param.** Needed for `<audio>`/`<a>` media elements, but query strings land in server/proxy logs, browser history, and `Referer` headers. (`server/src/auth/lan-token.ts:22`, `web/src/main.tsx:14-24`) — *Mitigated: the guard is now a factory — `/api` is `Authorization: Bearer` only, and `?token=` is accepted on `/media` alone, where elements genuinely can't set headers. Every response sends `Referrer-Policy: no-referrer` so it no longer leaks via `Referer`, and `main.tsx` already scrubs it from the URL. Full removal is the §4 "signed short-lived media URLs" item.*
- [x] **P3 — Windows secrets stored plaintext with no ACL hardening.** `chmod 600` is best-effort and ignored on Windows, so all Plaud tokens + `lanToken`/`webhook.secret` sat in cleartext in `%APPDATA%\applaud\settings.json` under whatever ACL was inherited. (`server/src/config.ts:32-36`) — *Fixed: `security/windows-acl.ts` runs `icacls /inheritance:r` once per install at startup (marker file), granting only the current user and SYSTEM; best-effort and skippable via `APPLAUD_SKIP_ACL_HARDENING=1`. The residual plaintext exposure and the DPAPI follow-up are documented in the README's Config section.
